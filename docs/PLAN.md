# 技术方案与架构决策（PLAN）

> 项目：三角洲口琴工坊（Delta Harmonica Studio）
> 文档性质：调研结论 + 技术选型 + 架构设计 + 实现要点 + 风险与路线图
> 相关调研原始报告：[game-harmonica.md](research/game-harmonica.md)（游戏机制）、[tech-stack.md](research/tech-stack.md)（技术选型调研）

---

## 1. 需求拆解

用户目标：在《三角洲行动》里自动吹「守夜人口琴」，并且：

1. **可录入乐谱**：人能舒服地输入/编辑简谱；
2. **可传入音乐文件并分析出简谱**（符合口琴演奏约束）；
3. **可存储音乐方案**；
4. 最终能在游戏内真实演奏。

拆成工程模块：

| 需求 | 对应模块 | 关键约束 |
|---|---|---|
| 乐谱录入 | 简谱 DSL + SVG 简谱编辑器 | 简谱记法完整、可往返序列化、拍号校验 |
| 音乐文件→简谱 | MIDI 导入 / 音频转谱 | 单声部、音域 38 音、量化、调性、可演奏性 |
| 音乐方案 | JSON 方案 + 本地曲库 | 可备份/迁移、原子写入、导入导出 |
| 游戏内演奏 | 演奏编排 + 高精度注入 | 权限（UIPI）、时序（毫秒级）、安全（焦点/光标/急停） |

## 2. 调研结论摘要（决定设计的事实）

### 2.1 游戏机制

- S11「群星」赛季新增 **守夜人口琴**：完成长弓溪谷佐拉任务链 → 邮件领取 → 放入 EDC 工具包 → 局内长按 `6` 打开轮盘取出 → 进入手动演奏界面。
- 官方自带 `R` 自动演奏**只能播放已解锁曲目，不能导入自定义谱**；自定义曲只能靠模拟手动按键。
- 声音全图可闻、会暴露位置；无冷却；单音，不能和弦。

### 2.2 键位（高置信）

| 简谱 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 高音1 |
|---|---|---|---|---|---|---|---|---|
| 按键 | Z | X | C | V | B | N | M | `,` |

- 鼠标**左键**=降八度、**右键**=升八度、**中键**=升半音；按多久响多久。
- 8 音键 + 3 修饰键组合 → 覆盖 **C3–C#6 连续 38 个半音**。
- 顺序必须是「先按住鼠标修饰键 → 稳定 ~24ms → 按音符键」；相邻音要留释放间隔。
- 只有升号没有降号：降号用等音改写（b7 → #6 或换八度）。

### 2.3 风险（必须写进产品）

- 游戏使用腾讯 ACE 反作弊；官方 2025-12 起升级鼠标宏打击、2026-07 重申「鼠标宏=外挂」，最高 **10 年封禁**。
- 官方禁用清单明确点名「模拟类脚本 / 按键精灵 / AutoHotkey / python 等自动脚本 / 鼠标宏」。
- 本软件只做 `SendInput` 用户态模拟，不注入进程、不读写内存、不装驱动、不做反检测；但这并不等于合规。
- 结论：产品必须首次启动强风险确认、默认安全闸门、不宣传「绝对安全」，并在文档中如实告知。**是否使用由用户自行决定并承担后果。**

## 3. 技术选型

### 3.1 决策：Electron 45 + React 19 + TypeScript

调研报告曾推荐 Python + PySide6（音频生态成熟）。最终选择 Electron，原因与本项目条件相关：

| 维度 | Electron + TS | Python + PySide6 | 结论 |
|---|---|---|---|
| UI 质量/开发效率 | Web 技术，简谱 SVG 排版、交互、样式非常成熟 | QPainter/Widgets 实现成本高 | **Electron 胜** |
| 音频分析 | 纯 TS DSP 可行（本项目已实现 YIN/onset/tempo，3 分钟音频 0.89s） | basic-pitch 等更强，但 Python 3.14 环境兼容与打包重 | 平手（本项目旋律为主，DSP 够用） |
| 原生注入 | koffi FFI 调 user32，`sizeof(INPUT)=40` 已验证 | ctypes 直接 | 平手（均已实测） |
| 性能/时序 | 主进程 hrtime + 自旋，实测毫秒级 | 同样可行 | 平手 |
| 打包体积 | ~250MB（Electron 运行时） | ~40-80MB | Python 胜 |
| 生态/维护 | 本机 Node 24 + npm 工具链完整，HMR 快 | 需额外 Python 依赖管理 | **Electron 胜** |

**结论：Electron 主方案已落地并完成全链路验证；体积换开发速度与 UI 质量。**  
音频分析保留升级路径：`basic-pitch` ONNX 可作为可选组件接入，不阻塞当前纯 DSP 方案。

### 3.2 关键依赖

- `electron-vite`（主/预加载/渲染三端构建 + HMR）
- `koffi`（动态调用 user32/winmm，N-API 预编译，无需 MSVC）
- `@tonejs/midi`（MIDI 解析）
- `vitest`（纯核心逻辑单测）
- 其余为 React / 原生 CSS（不引入 UI 框架，减少依赖与体积）

### 3.3 为什么不用 Interception / 驱动 / 硬件

- Interception 需要装驱动、LGPL 商用限制，且对 ACE 风险更高；
- 硬件 Arduino HID 可靠但门槛高（要买板子、刷固件），留作后续可选后端；
- `SendInput` 用户态、无内核组件，是本类工具的主流实现，风险相对最小（但不是零风险）。

## 5. 数据模型与简谱 DSL

### 5.1 为什么用「绝对拍位」

`ScoreNote` 使用 `startBeat + duration`（而非隐式顺序）。这样 MIDI/音频量化的非均匀节奏、休止空档、跨小节音都能无歧义表达；播放/编辑/序列化共用一套数据。

```ts
interface ScoreNote {
  id: string;
  degree: 0 | 1..7;      // 0 = 休止
  accidental: -1 | 0 | 1;
  octave: number;        // 相对简谱基准八度
  startBeat: number;     // 四分音符 = 1 拍
  duration: number;
  tie: boolean;          // 连音线（标在前一个音上）
}
interface ScoreMeta {
  title; artist?; tempo;            // 四分音符 BPM
  meter: { num; den };
  keyRoot: 0..11;                   // 1 = 哪个音
  baseOctave: number;               // 1 所在八度（4 → C4=60）
}
```

### 5.2 DSL 语法

- 音级 `1-7`、休止 `0`、升降 `#4` / `b7`、八度 `1'` / `,1`；
- 时值：`5_`（半拍）、`5.`（附点）、`5-`（延长一拍）、`5:1.25`（精确拍数）、`5~ 5`（连音）；
- 小节线 `|` 用于校验拍号；`# 标题：` 等头部元信息、`//` 注释。

解析器容错：全角字符归一化、逐 token 诊断（行/列/原文）、非法 token 不抛异常。序列化保证 round-trip（跨小节音不再产生错误小节线）。

## 6. 键位映射与音域

- 物理组合枚举：`key ∈ {1..7, i} × octaveShift ∈ {-1,0,+1} × semitone ∈ {0,1}`，去重后按「修饰键数量 → 八度偏移 → 半音」排序。
- 绝对音高约定 `1=C4=60`（游戏绝对音高未公开，仅用于内部换算与试听；不影响游戏实际发声）。
- 支持「兼容模式」：`allowModifierCombos=false` 时禁止「八度+半音」组合（若实机发现半音只在中音区生效可切换）。
- 降号/超音域：统一以「等音 + 八度折返 + 整体移调」解决；折返会在 UI 明确提示数量。

## 7. 演奏编排算法（核心）

`planPerformance(score, options)` 流程：

1. **音高序列提取**：连音合并、重叠截断（单声部）。
2. **全局移调**：
   - 固定移调（用户选择）或 `'auto'`：枚举 -11..+11 半音，按
     `不可演奏数×10000 + 折返数×40 + 修饰键数×8 + |移调|×0.5` 计分取最优。
3. **逐音候选组合**：目标 MIDI → 可用物理组合列表；超音域按 ±12 折返（可关闭折返）。
4. **修饰键切换 DP**：状态为上一层候选组合，转移代价 = 需要松开/按下的鼠标键数量（+ 微小修饰键偏好）。得到全曲修饰键切换最少的键位序列。
5. **节奏可行性**：
   - 相邻音间隔过短（<28ms）的音会被丢弃并警告（保证事件不会变成和弦）；
   - 每个音的保持时长 = `min(时值-释放间隔, 下个音起点-必需切换时间)`，且不低于 4ms；
   - 需要切换修饰键时预留完整稳定时间（默认 24ms），不需要时只留释放间隔。
6. **生成毫秒事件**：
   - 先按 `修饰键 down → settle → 音符 keydown → hold → keyup → 反序释放` 生成；
   - 起点留白 90ms，所有事件按绝对时间轴对齐；
   - 收尾释放全部鼠标修饰键。
7. **validatePlan**：单测校验「事件有序、无和弦、修饰键状态正确、结束无残留键」。

时序默认值全部可在设置页调整。

## 8. 输入注入与安全设计（实测经验）

### 8.1 技术事实（本机实测）

- `koffi` + `SendInput` 在 Electron 45 主进程可用；`sizeof(INPUT)=40`。
- 键盘用**物理扫描码**（`KEYEVENTF_SCANCODE`）注入，规避中文输入法与键盘布局。
- 游戏以 High 完整性（管理员）运行，**非提权进程的 SendInput 会被 UIPI 静默丢弃**（返回成功但没有事件）。
- 把目标窗口切前台需要 `AttachThreadInput + SetForegroundWindow + SetFocus` 组合（已封装）。
- **鼠标事件投递到「光标所在的窗口」，不是「焦点窗口」**：因此演奏前必须把光标移入游戏窗口，否则八度/半音修饰键失效甚至误点其他程序。这是本项目实测发现的关键坑。

### 8.2 安全机制

| 机制 | 说明 |
|---|---|
| 首次风险确认 | 必须勾选才能使用；如实告知最高 10 年封禁风险 |
| 权限检测 | 未提权时状态栏警示并在开始演奏时阻止（附「以管理员重启」按钮 + UAC） |
| 目标窗口校验 | 开始前检查前台窗口是否为所选游戏窗口；可自动切前台 |
| 光标保护 | 开始前自动把光标移入游戏；演奏中光标离开游戏立即停止 |
| 焦点看门狗 | 80ms 轮询，游戏失焦立即停手并释放全部按键 |
| 全量松键 | 停止/异常/退出/失焦都会释放已按下的键盘与鼠标键 |
| 急停 | F12 全局热键；F9 开始/停止 |
| 安全确认 | 谱面需要鼠标左/右键（游戏内开火/开镜）时，必须勾选「已取出口琴」才能开始 |
| 自检 | 应用内真实注入 Z/X/中键/逗号到本窗口，验证链路；失败给排查建议 |

### 8.3 打包清单的特殊决策

- Electron 45 在 **中文 exe 文件名**与 **requireAdministrator 清单**下会触发原生 `STATUS_BREAKPOINT` 崩溃（已实测定位）。
- 因此：exe 名用 ASCII（`DeltaHarmonicaStudio.exe`）、安装包以 `asInvoker` 启动；窗口标题、快捷方式、安装界面仍是「三角洲口琴工坊」。
- 需要注入游戏时，应用内点击「以管理员身份重启」→ PowerShell `Start-Process -Verb RunAs` 触发 UAC，得到高完整性进程后再注入。

## 9. 音频转谱管线

`transcribeMelody(pcm, sampleRate)`：

1. 峰值归一化 → 线性降采样到 22.05kHz；
2. 起音检测：Hann 窗 FFT 幅度谱半波整流谱通量 → 峰值 → onset 时间 + 包络；
3. 节拍：onset 包络自相关 + 谐波加权 + 120BPM 先验，输出 BPM/置信度；
4. YIN 基频：差分函数 + CMNDF + 阈值 + 抛物线插值（用 FFT 互相关加速），clarity < 0.3 视为无音高；
5. 后处理：5 帧中值滤波、八度离群回填、迟滞状态机切音（0.7 半音需 2 帧确认、1.15 强跳变立即切）；
6. 合并 ≤30ms 碎音、过滤 <70ms 音符，输出原始旋律（秒）；
7. 上层 `melodyToScore` 做量化（1/16 默认）、调性检测（Krumhansl）、自动基础八度、单声部去重叠、简谱写法生成。

**明确限制**：单声部假设、无伴奏分离；成品歌建议用 MIDI 或直接粘贴简谱。性能：3 分钟 44.1kHz 音频 ~0.89s。

## 10. MIDI 导入

- `@tonejs/midi` 解析；逐轨统计音符数/音域/平均音高/单音比例/是否鼓轨；
- 默认选轨：排除鼓轨 → 音符数 ≥8 → 单音比例 → 平均音高；用户可切换；
- 单音化：重叠保留高音、前音在下一音起点截断、同音重叠合并；
- BPM 取首个 tempo（多 tempo 警告），量化网格可配；调性自动检测；生成 Score。

## 13. 实机验证记录（2026-11-18 · 真实对局内）

在用户真实对局、手持「守夜人口琴」手动演奏界面下完成（ACE-Tray 反作弊常驻）：

| 验证项 | 结果 |
|---|---|
| 游戏窗口识别 | `DeltaForceClient-Win64-Shipping.exe`，窗口标题「三角洲行动」，进程名匹配成功 |
| 前台/焦点切换 | AttachThreadInput + SetForegroundWindow + SetFocus 成功，前台校验通过 |
| 键盘注入 | `Z X C` = 1 2 3 均发声，音高正确 |
| 中键半音 | 中键 + `Z` 发出升半音（#1），中键无其它副作用 |
| 基础节奏 | `1 1 5 5`（Z Z B B）节奏清晰，重复音重触发正常 |
| 右键高八度 | 右键 + `Z`/`C` 发出高音 1 / 高音 3 |
| 左键低八度 | 左键 + `Z`/`C` 发出低音 1 / 低音 3 |
| 八度+半音组合 | 右键+中键+`Z`、左键+中键+`C` 均得到预期升高/降低半音，**组合叠加可用** |

| 软件完整自动演奏 | 自动识别游戏窗口 → 3s 倒计时 → **24/24 输入事件按时间轴发出**（7.57s，含右键高音）→ 正常 finished；实机听到的《风声未止·破晓》旋律、节奏、八度均正确，无异常 |

结论：

- 38 音模型、三个鼠标修饰键、组合叠加均在实机成立 → 软件默认 `allowModifierCombos=true` 与排键 optimizer 的假设正确，无需切换兼容模式；
- SendInput（物理扫描码）可被本游戏接收，无需硬件注入即可工作；
- 关键教训再次确认：**鼠标事件投递到光标所在窗口**，必须保证光标在游戏窗口内（软件已加保护）；
- 本节未覆盖：高 BPM 密集音符、长时间连续演奏、焦点/光标保护的主动触发测试、打包版在游戏内的完整演奏 —— 建议在训练场/单人安全场景补测。

## 14. 已知限制 / 风险

1. **合规风险**：模拟输入属于官方定义的第三方脚本范畴，最高 10 年封禁；产品已尽告知义务，不提供任何规避。
2. Electron 45 打包限制（中文 exe 名 / requireAdministrator）→ 已用 ASCII 名 + 运行时提权绕过。
3. 键位表固定，自定义逐键重映射待做；任务曲谱的八度/半音细节各攻略有分歧，需实机校准。
4. 音频转谱对带伴奏歌曲效果有限。
5. 软件体积约 250MB（Electron 运行时）。
6. 未做真机游戏内验证（本开发环境无法实际进入对局）；时序参数均可在设置页微调。

## 16. v0.2 升级记录（UI / 悬浮窗 / 热键 / 双音色 / 主旋律扒谱）

### 16.1 目标

在不改变既有注入/排程核心的前提下，按「UI 完整优化 + 新功能」要求完成：①悬浮操作界面与全局快捷键；②应用内试听（口琴/钢琴双音色）；③扒谱以主旋律为核心；④整体 UI/UX 重做。

### 16.2 应用外壳重构

- 旧结构：Sidebar + StatusBar + 页面滚动，播放控制只在演奏台。
- 新结构：`Sidebar + TopBar + 页面滚动 + 底部常驻 TransportBar`；顶栏显示当前曲谱/输入通道状态/热键提示/悬浮窗入口；底部播放条提供双音色试听、音量、进度、开始/停止/急停与快捷键提示。
- 新增全局上下文：
  - `PreviewProvider`：试听状态与音色/音量，任何页面可调用；
  - `PerformanceProvider`：当前曲谱的演奏计划、移调/速度、安全确认、开始/停止、进度与音符高亮；F9 命令与自动测试模式统一在此处理。
- 页面级重做：演奏台（谱面 + 演奏设置/计划/键位谱 Tab）、编辑器（每行小节数/缩放/内嵌试听）、智能导入（主旋律参数/拖拽/双音色 A/B）、方案库（搜索/筛选/排序/网格列表/批量管理）、设置（6 个 Tab）。

### 16.3 悬浮控制窗

- 独立 `BrowserWindow`：`frame:false, transparent:true, alwaysOnTop:'screen-saver', skipTaskbar:true, focusable:false, showInactive()`，不抢游戏焦点；
- 页面 `src/renderer/src/overlay/OverlayRoot.tsx`，通过 `overlay:state` 接收主窗口同步的曲谱/播放状态/快捷键；
- 主进程 `OverlayWindowManager`：位置持久化（moved 防抖写设置）、透明度/置顶/显隐、`resetPosition`（position=null 回右下角）；
- 按钮 → `overlay:command` → 主进程分发（开始/停止/急停/显示主窗口/隐藏悬浮窗）；
- 限制：独占全屏游戏无法被覆盖，需无边框窗口；透明窗口自截图验证 alpha 正确（角落 α≈3、卡片 α≈240）。

### 16.4 可配置全局快捷键

- `HotkeyManager`（主进程）统一 `globalShortcut` 注册/注销、重复组合检测、注册失败原因记录；
- 设置页 `HotkeyRecorder` 捕获组合键生成 Electron accelerator，保存后调用 `settings:update`，主进程同步重建注册并返回状态；
- 录制期间通过 `hotkeys:setRecording` 临时注销全部热键，避免录制 F9 时误触；
- 默认：`F9` 开始/停止、`F10` 急停、`Ctrl+Alt+O` 悬浮窗、`Ctrl+Alt+M` 主窗口（本机 4/4 注册成功；初版 F12/F8 被系统占用已替换）。

### 16.5 双音色试听

- 纯 Web Audio 合成，无外部采样：
  - 口琴：PeriodicWave 簧片泛音 + 慢起音/渐强 + 5.3Hz 轻颤音 + 带通气流声；
  - 钢琴：击弦瞬态 + 泛音列 + 指数衰减 + 轻微失谐 + 击弦噪声；
- 每个音符按演奏计划的 `startMs/holdMs` 绝对排程，与注入计划共享同一份 `PlaybackPlan`；
- 音量/音色持久化到 `settings.preview`。

### 16.6 主旋律提取（音频扒谱）

新增纯 TS 模块（零依赖、Node 可测）：

- `hpss.ts`：Hann 1024/hop 256 STFT，时间轴/频率轴中值滤波 HPSS + Wiener 软掩码，可选重建谐波时域信号；
- `salience.ts`：对数压缩 + 噪声底扣除 + 1~6 次谐波累加 + 基频支撑度加权 + 音域先验；`estimatePolyphonyScore` 输出复音程度；
- `melody.ts`：归一化/降采样 → HPSS → 谱通量起音 + BPM → 显著度 → auto 选路；
  - monophonic：YIN + 迟滞切分；
  - polyphonic：Viterbi（音高连续性/大跳/超八度惩罚/起音换音折扣 + skyline 顶音加权）+ 八度校正；
  - 两遍切分、碎音合并、最短音符过滤、音域约束（默认 C3–C6）、maxNotes 截断、warnings/置信度。
- 集成：`renderer/src/audio/melody-adapter.ts` 映射 `AudioAnalysisSettings`，异常回退单声部 YIN；导入页展示 method/BPM/置信度/有声帧占比。
- 性能：60s 44.1kHz 合成音频 0.72s（要求 <6s）。

## 17. v0.3 鼠标宏导出与触发键位表

### 17.1 目标

在「软件内直接注入」之外，提供第二条可用路径：把同一份演奏计划导出为**鼠标宏软件可回放的脚本**，并给出**按曲谱编排的触发键位表**（每个音按哪个音键 + 哪个鼠标修饰键、何时按、按多久）。适用于不想常驻运行本软件、或只用鼠标宏驱动的用户。

### 17.2 设计原则

- **同源**：导出直接消费 `PlaybackPlan.events`（键盘事件带物理扫描码/虚拟键码，鼠标事件带按钮），与 `PlaybackController` 注入的事件流完全一致；移调、折返、修饰键 DP 切换都已在此前算好。
- **零依赖**：脚本生成是纯字符串拼接，位于 `src/core/export/macro.ts`，可单测。
- **可配置触发**：AHK 触发键（默认 F9，或 `XButton1/XButton2` 鼠标侧键）；罗技 OnEvent 触发按钮（默认 5=前进侧键，可改 4）。
- **安全可中止**：AHK 用 `playing` 标志 + `Wait()` 轮询，F10 `Reload` 立即中止；罗技 Lua 再按一次侧键置 `playing=false`，`Wait()` 在 10ms 内退出。

### 17.3 四种导出格式

| 格式 | 实现要点 |
|---|---|
| AutoHotkey v1 `.ahk` | 键盘统一用扫描码 `{sc02C down/up}`（布局无关，与软件内注入一致）；鼠标用 `{LButton/MButton/RButton down/up}`；事件间隔生成 `Wait(ms)`；开头写好管理员运行、无边框窗口、急停说明 |
| 罗技 G HUB Lua `.lua` | `OnEvent` 监听 `MOUSE_BUTTON_PRESSED` 侧键触发；`PressKey("z")`…、`comma` 为逗号键名；鼠标编号 `1=左 2=中 3=右`（已按 Logitech Lua 文档核对）；`GetRunningTime()` + `Sleep(10)` 实现可中断延时 |
| 通用 CSV `.csv` | UTF-8 BOM；列：序号/时间ms/距上一事件ms/动作/设备/键位/扫描码/说明；每行可直接录入支持"按键+延时"的宏编辑器 |
| 触发键位表 `.trigger.md` | ① 全音域 C3–C#6 共 38 个半音的最佳触发映射（音名/MIDI/简谱级数/八度偏移/键位记号/音键/鼠标修饰）；② 本曲逐音触发表（整数 ms 开始/保持/结束、音名、触发方式）；③ 组合使用统计；④ 输入事件统计；⑤ 计划 warnings |

### 17.6 已知限制

1. 宏软件 Sleep 分辨率有限（AHK/G HUB 通常 10–15ms），极快节奏可能有轻微时序抖动；
2. AHK/G HUB 必须以管理员运行，否则游戏静默丢弃输入；
3. 若本软件同时运行，F9 全局热键与 AHK 默认 F9 会冲突——建议宏触发改用鼠标侧键，或先退出软件；
4. 宏软件同样属于第三方模拟输入，合规风险与软件内注入一致；
5. 罗技旧版 Gaming Software 与新 G HUB 的 API 基本兼容，但按键编号/界面路径可能有差异，导出文件内已注释映射；
6. 其他品牌宏软件不保证支持 Lua/AHK，可优先用 CSV 时序表逐行录入。
