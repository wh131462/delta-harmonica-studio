# 三角洲口琴工坊 · 产品设计文档

本文档描述三角洲口琴工坊的产品定位、设计原则、功能结构、关键流程、数据模型、技术架构与安全约束。面向产品、设计、开发和测试，解释「为什么这样设计」，而不是逐步操作说明；安装、启动与最短使用路径见仓库 [README](../README.md)。

文档只记录相对稳定的产品决策，不记录版本号、发布记录、测试数量或一次性验收数据。

## 1. 产品定位

### 1.1 一句话描述

把简谱、MIDI 或音频转换成《三角洲行动》「守夜人口琴」可演奏的物理键位序列，在游戏内自动演奏，或导出为鼠标宏、键位谱供其他方式回放。

### 1.2 用户问题

- 游戏内置的自动演奏只能播放官方已解锁曲目，无法导入自定义曲谱。
- 游戏口琴是单音乐器，实际演奏依赖 8 个音键与鼠标修饰键的组合，人工记谱和找键位成本高。
- 社区曲谱常以按键串或简谱文本流传，缺少统一的可编辑、可试听、可校验载体。
- 不启动游戏时无法练习；玩家需要先熟悉按法、节奏和段落，再进入对局。
- 部分用户更希望用鼠标宏软件回放，而不是常驻运行一个注入程序。
- 带伴奏的歌曲、清唱和 MIDI 需要不同的转谱路径，单一算法无法覆盖所有素材。

### 1.3 目标用户

- 希望用自定义曲目演奏的 PC 端玩家。
- 需要慢速跟谱、反复练习某一段落的玩家。
- 使用 AutoHotkey、罗技 G HUB 或其他宏工具的玩家。
- 制作曲谱、键位谱或演示视频的内容创作者。
- 需要把曲谱保存、备份、分享给朋友的用户。

### 1.4 核心场景

1. 在编辑器里写一段简谱，试听后到游戏里演奏。
2. 导入 MIDI 或音频，自动生成单声部简谱，校正后保存。
3. 把某几小节变成练习轨道，慢速循环，按对音高并踩准拍点。
4. 在游戏内用悬浮窗或全局快捷键控制开始、停止和急停。
5. 把当前曲谱导出为 AHK、G HUB Lua、CSV 或键位表，在其他机器或宏软件中回放。
6. 从方案库检索、收藏、备份和迁移曲谱。

### 1.5 产品目标

- 打通「曲谱创作 / 导入 → 试听 → 练习 → 游戏演奏 → 导出」的完整闭环。
- 让自动演奏的按法尽可能少切换修饰键，并在超音域时给出可解释的折返或移调。
- 让练习与游戏演奏使用同一套键位、移调和判定语义，练习成果可直接迁移。
- 在任何停止路径上都不留下按住的键，尽量降低误操作风险。
- 所有曲谱和设置默认保存在本机，不依赖账号、云端或网络。

### 1.6 非目标

- 不绕过、不对抗反作弊，不提供任何防封或反检测能力。
- 不支持多声部、和弦或复调演奏；游戏口琴本身是单音乐器。
- 不做手游端、主机端或云端曲库。
- 不修改游戏文件、不读写游戏内存、不安装内核驱动。
- 不做通用 DAW、专业制谱软件或音乐教学平台。
- 不替用户判断使用场景是否合规；产品只负责如实告知风险。

## 2. 游戏侧约束

产品设计必须建立在游戏机制的事实之上。以下约束是最稳定的设计输入：

### 2.1 口琴机制

- 口琴通过任务链获得，放在 EDC 工具包中，局内通过轮盘取出并进入演奏界面。
- 官方自动演奏只能播放已解锁曲目，不能导入自定义谱；本产品模拟的是手动演奏按键。
- 口琴是单音乐器，不能同时发声多个音；声音全图可闻，会暴露位置。
- 演奏界面存在手动演奏状态，软件开始前需要用户确认已取出口琴。
- 游戏版本可能调整键位、任务或界面，因此需要保留校准与自检能力。

### 2.2 键位与音域

| 简谱 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 高音 1 |
|---|---|---|---|---|---|---|---|---|
| 按键 | Z | X | C | V | B | N | M | `,` |

- 鼠标左键为降八度，右键为升八度，中键为升半音；可组合使用。
- 8 个音键与 3 个鼠标修饰键组合，覆盖 C3–C#6 共 38 个连续半音。
- 游戏只有升号语义，降号通过等音改写、八度折返或整体移调解决。
- 修饰键必须先按住并稳定，再按音符键；否则高音 / 低音可能被识别成中音。

### 2.3 输入环境

- 游戏以较高完整性级别运行。Windows UIPI 会静默丢弃低权限进程的模拟输入，因此注入前必须提权。
- 鼠标事件投递到光标所在的窗口，而不是焦点窗口。演奏前必须把光标移入游戏窗口，否则八度 / 半音修饰键会失效，甚至误点到其他程序。
- 游戏窗口可以通过标题与进程名识别，但窗口模式会影响悬浮窗是否可见。
- 全局快捷键可能被系统、游戏或其他软件占用，注册结果必须向用户可见。

### 2.4 风险约束

游戏官方将第三方软件、脚本、鼠标宏自动操作认定为违规，存在封禁风险。软件只做用户态 `SendInput` 模拟，不注入进程、不读写内存、不安装驱动、不做反检测，但这些事实不等于合规或安全。产品必须：

- 首次启动展示风险声明，并要求明确确认。
- 不在文案中承诺「安全」「不会封号」。
- 在 README、设置页和导出文件中保留风险提示。
- 把是否使用、何时使用的决定权交给用户。

## 3. 设计原则

1. **安全先于便利**：权限、焦点、光标、急停和全量松键优先于「少点一次」的体验。
2. **同一份计划，多种输出**：试听、游戏注入和宏导出共享同一个 `PlaybackPlan`，避免试听、软件演奏和宏回放出现节奏或按法差异。
3. **确定性优先于炫技**：排键可解释、可预览、可校验；自动移调与折返要给出统计和警告，而不是静默修改。
4. **练习与演奏同构**：练习只监听本窗口，但键位、移调、音色和判定语义与游戏演奏保持一致。
5. **真实反馈**：试听使用真实采样音色；演奏中高亮当前音符；状态、错误和权限结论只在一处说清楚。
6. **渐进披露**：常用操作直接可见，时序、兼容模式、音频参数和宏兼容性放在次级面板。
7. **可逆与可恢复**：编辑可撤销，导入先预览，练习成绩不落盘，任何停止路径都不残留按键。
8. **本地优先**：曲谱、设置、音频分析和试听都在本机完成，不上传用户内容。
9. **一致与可访问**：颜色、间距、焦点、弹窗和状态语义统一由设计令牌与组件约束。
10. **诚实边界**：对单声部、音域、转谱质量、宏时序和游戏版本差异如实说明。

## 4. 产品结构

### 4.1 功能域

| 功能域 | 用户目标 | 关键能力 |
|---|---|---|
| 曲谱编辑 | 从零写谱或修改导入结果 | 音符序列编辑、音级 / 八度 / 升降 / 时值、撤销重做、从指定音试听、保存方案 |
| 实时录入 | 用游戏键位快速记录旋律 | 按 BPM 量化、1/4–1/16 网格、悬浮录制条、插入 / 追加、撤销 |
| 智能导入 | 从现有音乐生成可演奏简谱 | MIDI 选轨与单音化、音频主旋律提取、调性 / 八度 / 量化、警告与置信度 |
| 演奏台 | 把曲谱可靠地送到游戏 | 目标窗口、移调、速度、折返、安全确认、计划预览、倒计时、播放高亮 |
| 练习 | 不启动游戏也能练 | 段落切片、变速、循环、等待模式、横向 / 下落谱面、逐音判定、节拍器 |
| 悬浮窗与热键 | 游戏内不切界面控制演奏 | 透明置顶、按钮、位置记忆、可配置全局快捷键、冲突提示 |
| 方案库 | 管理和迁移曲谱 | 本地保存、搜索 / 筛选 / 排序、收藏、批量操作、导入导出 |
| 导出 | 在软件外使用曲谱 | 简谱文本、键位谱、方案 JSON、AHK v1/v2、G HUB Lua、CSV、触发键位表 |
| 设置与自检 | 让输入链路可诊断 | 权限状态、目标窗口、输入方式、时序、音频、快捷键、悬浮窗、风险声明 |

### 4.2 页面结构

主窗口由固定侧栏、顶栏、页面滚动区和底部常驻播放条组成：

- **侧栏**：品牌、演奏台、练习、简谱编辑器、智能导入、音乐方案库、设置与校准、权限状态。
- **顶栏**：当前曲谱、输入通道状态、悬浮窗入口、快捷键提示。
- **底部播放条**：试听 / 停止、音色、音量、演奏进度、开始 / 停止，任何页面都能控制。
- **设置页**：输入与权限、演奏时序、快捷键、悬浮窗与外观、音频分析、风险与关于。
- **独立窗口**：透明悬浮控制窗、输入自检弹窗、风险声明弹窗、全屏练习舞台。

页面结构遵循「一个页面只做一类事」：编辑不负责演奏，演奏台不负责转谱，设置不重复解释同一状态。

### 4.3 全局状态与反馈

- 试听状态与演奏状态由全局上下文管理，页面切换不会丢失当前曲谱或播放状态。
- 顶栏、播放条、悬浮窗共用同一套演奏状态文案：待命、倒计时、演奏中、演奏完成、已停止、出错、焦点丢失已停止。
- 同一状态只提示一次。权限结论在侧栏，输入通道结论与提权入口在顶栏，完整原因与操作在设置页；其他位置只引用，不重复展开。
- Toast 用于操作结果，不用于持续性状态；弹窗用于风险确认、输入自检等需要阻断的流程。

## 5. 核心概念与数据模型

### 5.1 简谱与绝对拍位

曲谱以「绝对拍位」而不是隐式顺序表达：每个音符记录 `startBeat + duration`，四分音符为 1 拍。这样可以无歧义地表达 MIDI / 音频量化后的非均匀节奏、休止空档和跨小节音；播放、编辑和序列化共用同一模型。

```ts
interface ScoreNote {
  id: string;
  degree: 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7; // 0 = 休止
  accidental: -1 | 0 | 1;
  octave: number;      // 相对简谱基准八度
  startBeat: number;
  duration: number;
  tie: boolean;        // 与紧随其后的同音高音符连音
}

interface ScoreMeta {
  title: string;
  artist?: string;
  tempo: number;       // 每分钟四分音符数
  meter: { num: number; den: 2 | 4 | 8 | 16 };
  keyRoot: number;     // 0 = C … 11 = B
  baseOctave: number;  // 1 所在的科学音高八度，4 → C4 = MIDI 60
}
```

`Score` 还包含 `id`、`schema`、`source`（手动 / 文本 / MIDI / 音频 / 内置）、创建与更新时间。曲谱本身不保存小节线位置，小节线由拍号与时值实时推导，避免编辑后出现陈旧排版。

### 5.2 音高与键位

- 内部统一用 MIDI 音高计算；简谱的 `keyRoot` 与 `baseOctave` 决定 `1` 的绝对音高。
- 游戏绝对音高未公开，`1 = C4 = MIDI 60` 只是内部换算与试听约定，不影响游戏实际发声。
- 物理组合 = 音键 × 八度偏移 × 半音偏移。软件枚举所有组合，并优先选择修饰键更少、切换更少的按法。
- 超音域时优先八度折返以保持原调；使用「自动移调」时，再在 -11…+11 半音内寻找折返更少、修饰键更少的调。折返与移调的数量都会在计划中提示。

### 5.3 简谱文本 DSL

DSL 用于文本导入、简谱导出和调试，不要求用户在日常编辑中手写。

| 语法 | 含义 |
|---|---|
| `1`–`7` / `0` | 中音区音级 / 休止 |
| `#4` / `b7` | 升 / 降号；降号在演奏时按等音处理 |
| `1'` / `,1` | 高八度 / 低八度，可叠加 |
| `5_` / `5__` | 半拍 / 四分之一拍 |
| `5.` / `5_.` | 附点 / 附点八分 |
| `5-` / `5--` | 延长到 2 拍 / 3 拍 |
| `5:1.25` | 精确拍数 |
| `5~ 5` | 连音线 |
| `\|` | 小节线，用于校验与排版 |
| `//` / `# 标题：` | 注释 / 头部元信息 |

解析器需要容错全角字符、逐 token 报错、不因单个非法 token 抛异常；序列化要保证 round-trip，并避免跨小节音产生多余小节线。

### 5.4 演奏计划

`PlaybackPlan` 是产品内部最重要的中间产物：

- 每个音符对应一个物理键位组合与开始 / 保持 / 结束毫秒时间。
- 每个输入事件包含设备类型、键位、物理扫描码、按下 / 松开与绝对时间。
- 计划同时包含可演奏性统计、折返数量、移调量、总时长和警告。
- 试听、注入和宏导出都消费同一份计划；任何参数变化都重新生成计划。

### 5.5 存储

```
<userData>/settings.json          # 设置、收藏、风险确认状态
<userData>/scores/<id>.dfh.json   # 完整曲谱与来源元数据
```

Windows 下用户数据目录通常为 `%APPDATA%\三角洲口琴工坊`。写入采用临时文件 + 重命名的原子方式；单个曲谱损坏不应阻止应用启动。首次启动播种内置示例曲库，包含公有领域 / 传统民谣，以及来源已标注的社区整理任务键位序。

## 6. 功能设计

### 6.1 曲谱编辑

编辑器把乐谱视为一条连续的「音符 / 休止」序列：

- 未选中音符时，输入音级或点击音级键盘会把新音追加到末尾；选中音符时则修改当前音。
- 八度、升降、时值既可作用于当前选中音，也可作为「下一个音」的默认属性。
- 修改时值后，后续音符自动前后移动，小节线重排；重叠音符按单声部规则整理。
- 每个音符有稳定 id，插入、删除和移动不应导致无关音符重新渲染或选中丢失。
- 支持从指定音符开始试听；试听使用当前音色与音量，不发送游戏按键。
- 撤销 / 重做覆盖音符增删改、时值调整、连音和顺序整理。
- 保存后写入方案库；未保存状态在顶栏和侧栏可见。

编辑器不要求用户理解 DSL；文本格式只作为导入 / 导出通道保留。

### 6.2 实时录入

实时录入解决「有旋律但不想逐个点音级」的问题：

- 按游戏键位演奏，软件按当前 BPM 把按键时间量化到 1/4、1/8 或 1/16 网格。
- 第一个音键按下时开始计时；按住鼠标修饰键再按音键可改变八度 / 半音。
- 录制条悬浮在窗口右下角，不改变页面布局、不遮挡谱面主体；录制期间数字键不会修改背后谱面。
- 未选中音符时追加到末尾，选中时插入到其后；写入后可撤销。
- 录制期间临时暂停全局热键，避免按 `F9` 等组合时误触发演奏。
- 音高按当前曲谱的调号与基础八度记谱；游戏口琴固定为 C 调，因此在非 C 调曲谱中按 `Z` 会被记成相应的音级，但实际音高不变。

### 6.3 MIDI 导入

MIDI 是质量最高的导入路径，设计重点是「少做假设，多给控制」：

- 解析所有轨道，统计音符数、音域、平均音高、单音比例和是否鼓轨。
- 默认排除鼓轨，优先选择音符足够多、单音比例高、平均音高合适的轨道；用户可手动换轨。
- 单音化规则：重叠时保留高音，前一个音在下一个音起点截断，同音重叠合并。
- 速度取第一段 tempo；多段变速给出警告，不假装支持完整变速。
- 量化网格可调；调性可自动检测或手动指定；生成后进入预览，不直接覆盖现有曲谱。
- 超音域、量化移动和单声部截断都要在结果中提示。

### 6.4 音频转谱

音频转谱以「主旋律优先」为目标，明确接受不完美：

- 管线：解码与归一化 → HPSS 谐波 / 打击分离 → 谐波显著度 → 起音检测与节拍估计 → 单声部 YIN 或复音 Viterbi 跟踪 → 八度校正 → 音域约束 → 量化 → 调性与基础八度推断 → 简谱。
- 分析模式：自动判断、强制单声部、复音主旋律。
- 可调参数：主旋律音域、最短音符、伴奏抑制、量化网格、BPM 覆盖。
- 复音模式使用显著度矩阵与 Viterbi 平滑，结合音高连续性、跳进惩罚、起音换音和 skyline 顶音权重；结果仍可能跳八度或漏音。
- 结果页展示方法、BPM、置信度与警告，并提供试听；确认后再保存，避免把错误结果直接覆盖进方案库。
- 适用边界：清唱、哼唱、口哨、单乐器独奏效果最好；强混响、旋律被伴奏掩蔽、低音区旋律仍不可靠。重要曲目优先使用 MIDI 或现成简谱。

### 6.5 演奏台

演奏台负责把「曲谱」变成「可执行的输入计划」，并保证执行前用户知道会发生什么：

- 曲谱选择、移调（固定值或自动）、速度覆盖、目标窗口选择。
- 计划预览：音符数、时长、移调量、折返数、修饰键使用、警告。
- 安全确认：如果计划会按下鼠标左 / 右键（游戏中对应开火 / 开镜），必须确认已取出口琴才能开始；只使用键盘与中键时给出明确说明。
- 开始前检查管理员权限、目标窗口和光标位置，倒计时后开始；倒计时内切回游戏。
- 演奏中高亮当前音符，底部播放条显示进度；停止、急停、失焦、光标离开窗口、正常结束都走全量松键。
- 提供键位谱与宏导出面板，方便核对按法或在软件外回放。
- 排练模式只走时间轴、不发送按键，用于核对节奏与计划。

### 6.6 练习

练习是独立于游戏的跟谱模式，核心是「可重复、可解释、不误发送」：

- 从当前曲谱选择起止小节，跨小节自动切片；连音合并，超音域自动折返。
- 速度范围 50%–125%，显示实际 BPM；每遍开始前走预备拍。
- 两种判定方式：计时判定按时间轴滚动，超过窗口未按记为失误；等待按键在每音停住，按对音高才继续。
- 两种谱面：横向滚动与按 8 个音键分列的下落式；共用同一份练习会话与时间轴，可随时切换。
- 判定只看音高与时间：完美 ±55ms、优秀 ±100ms、良好 ±150ms；同音高的不同按法都算正确。
- 统计准确率、连击、平均偏差与判定分布；准确率 = 命中权重（完美 1 / 优秀 0.8 / 良好 0.5）÷（已判定目标音 + 错音）。
- 辅助：节拍器重拍加高音、按下音键立即发声、失误低声提示、循环本段。
- 练习只监听本窗口的键盘 / 鼠标，不向游戏发送任何按键；窗口失焦自动暂停；成绩不落盘。
- 练习期间段落、速度、模式和移调锁定；谱面显示可自由切换。

### 6.7 悬浮窗与全局快捷键

悬浮窗解决「游戏内不想切窗口」的问题，但必须避免抢焦点：

- 独立透明置顶窗口，关闭边框、任务栏图标，使用 `focusable: false` 与 `showInactive()`。
- 显示当前曲谱、目标窗口、播放状态、倒计时与进度；按钮包括开始 / 停止、急停、显示主窗口、收起。
- 位置拖动后记忆；透明度、置顶、快捷键提示可配置；重置位置回到右下角。
- 游戏使用独占全屏时系统不允许覆盖，需切无边框窗口；此时仍可用全局快捷键。
- 快捷键默认 `F9` 开始 / 停止、`F10` 急停、`Ctrl+Alt+O` 悬浮窗、`Ctrl+Alt+M` 主窗口，均可录制修改。
- 录制期间临时注销旧热键；保存后立即重新注册，并显示每项注册状态与冲突原因。

### 6.8 方案库

方案库是曲谱的本地管理中心：

- 曲谱以 JSON 保存，包含完整 Score 与来源元数据；支持备份与跨机器迁移。
- 搜索、按来源筛选、收藏筛选、排序、网格 / 列表视图。
- 卡片操作：演奏、编辑、导出、收藏、删除；支持批量管理。
- 导入支持方案 JSON、简谱文本和 MIDI；音频走智能导入。
- 首次启动提供内置示例曲库；来源在曲谱元信息中标注。
- 编辑中的未保存状态与已保存方案区分，避免误以为什么都已写入磁盘。

### 6.9 导出与鼠标宏

导出分为两类：给人看的谱，和给宏软件执行的脚本。

- **简谱文本**：DSL 格式，可再次导入编辑器。
- **键位谱**：按小节分组，标注音键与鼠标修饰，照着按即可。
- **方案 JSON**：完整曲谱与元数据，可迁移、可备份。
- **AutoHotkey v1 / v2**：使用物理扫描码发送键盘、鼠标键作为修饰，按绝对时间轴延时；触发键默认 `F9`，可改为鼠标侧键；`F10` 重新加载即中止。
- **罗技 G HUB Lua**：绑定鼠标侧键，按一次开始、再按一次中止。
- **CSV 时序表**：每行包含时间、间隔、按下 / 松开、设备、键位与扫描码，适合支持「按键 + 延时」的宏编辑器。
- **触发键位表**：全音域 38 个半音的推荐按法、本曲逐音触发表、组合统计、事件统计和宏软件兼容性。

所有宏导出必须消费当前 `PlaybackPlan`，保证移调、速度、折返和修饰键切换与软件内演奏一致。宏软件需要管理员权限运行，延时精度受宏软件限制；不要与软件内演奏同时启动。

品牌兼容性原则：宏由宏软件执行，与鼠标品牌无关。只有罗技 G HUB 公开提供脚本引擎；其他品牌只提供录制或私有配置，因此不伪造品牌格式，统一由 AHK 或 CSV 兜底。

### 6.10 设置与自检

设置页按任务分组，避免把所有选项堆在一页：

- **输入与权限**：输入方式（模拟注入 / 排练 / 串口预留）、管理员状态、目标窗口、输入通道自检、兼容模式。
- **演奏时序**：修饰键稳定时间、相邻音释放间隔、最短保持、修饰键切换间隔、开头留白；支持恢复默认。
- **快捷键**：四项全局热键的录制、注册状态、冲突原因、恢复默认。
- **悬浮窗与外观**：透明度、置顶、快捷键提示、重置位置。
- **音频分析**：分析模式、音域、最短音符、伴奏抑制、量化与调性。
- **风险与关于**：官方风险公告、版本信息、数据目录、风险声明。

输入通道自检向本窗口真实注入键盘、鼠标中键与组合键事件，并列出实际收到的事件。它回答的是「模拟输入在本机是否可用」，而不是「游戏是否一定接收」。

## 7. 关键流程

### 7.1 首次启动

1. 启动页加载设置、曲库与输入通道能力。
2. 展示风险声明，用户勾选确认后才能进入。
3. 主窗口载入最近曲谱或内置示例。
4. 用户在演奏台选择目标游戏窗口，必要时运行输入通道自检。
5. 选择曲谱、试听、练习或直接开始演奏。

设计要点：首次启动不自动发送任何按键；风险确认状态持久化；权限不足时仍允许试听、编辑和练习。

### 7.2 从曲谱到游戏演奏

1. 新建 / 导入 / 编辑曲谱并保存到方案库。
2. 在演奏台确认移调、速度与折返结果。
3. 选择目标窗口；如计划使用鼠标左 / 右键，完成安全确认。
4. 开始演奏，倒计时内切回游戏。
5. 软件按绝对时间轴发送输入；焦点或光标异常时立即停手。
6. 结束、停止或急停后释放全部按键。

### 7.3 练习

1. 选择曲谱与起止小节。
2. 选择速度、判定方式和谱面样式。
3. 预备拍后开始；按音键，软件只监听本窗口。
4. 实时查看判定、连击、偏差与准确率。
5. 可循环本段、切换谱面或进入全屏；结束时不向游戏发送任何输入。

### 7.4 宏回放

1. 在演奏台或方案库选择导出格式与触发方式。
2. 导出前确认移调、速度与折返结果。
3. 在宏软件中以管理员权限加载脚本并绑定触发键。
4. 游戏内触发回放；需要中止时使用脚本定义的急停方式。
5. 不与本软件内演奏同时启动，避免双触发。

## 8. 界面与交互设计

### 8.1 视觉语言

界面按「夜间乐器工作台」组织：石墨底色、单一琥珀聚光灯、青蓝系统信号。用排版、留白和层级表达结构，而不是用卡片、描边和背景晕染堆叠。

- 曲谱是主角，界面 chrome 不抢注意力。
- 琥珀色只用于当前主操作与播放状态；青蓝用于系统状态与焦点。
- 同一页面只保留一个主要操作层级；破坏性操作不使用强调色。
- 数据只在被使用的地方出现一次，例如音符数与时长只在播放条显示。

### 8.2 令牌与组件

- 颜色、字号、间距、圆角、动效、层级和骨架尺寸集中在 `src/renderer/src/styles/tokens.css`。
- 基元组件样式定义在 `components.css`：按钮、卡片、表单、标签页、分段控件、徽标、提示、弹窗、Toast、谱面表面等。
- 应用外壳由 `layout.css` 定义：固定侧栏、顶栏、底部播放条、启动页。
- 页面只组合基元与业务组件，不重写外观；页面专属样式放在 `page-*.css`。
- 修改界面前先阅读设计规范；界面改动必须通过类型检查、单元测试、构建和逐页截图核对。

### 8.3 状态呈现

- 演奏状态在顶栏、播放条、悬浮窗使用同一文案和颜色语义。
- 权限不足、目标窗口缺失、热键冲突、音频分析置信度低等状态给出结论和下一步动作，不只显示错误码。
- 计划警告在开始前展示，演奏中不弹出打断性弹窗。
- 空状态提供下一步入口：没有曲谱时引导新建 / 导入，没有目标窗口时引导刷新和自检。
- 高风险确认使用阻断弹窗；普通操作结果使用 Toast。

### 8.4 可访问性

- 全站提供 `:focus-visible` 焦点环，键盘可到达所有主要操作。
- 弹窗支持 `Esc` 关闭、焦点回收和 Tab 循环。
- Tab 组件具备 `role`、`aria-selected` 与方向键操作。
- 正文对比度不低于 4.5:1；谱面纸墨对比单独校验。
- 图标按钮提供可读名称；状态不只靠颜色表达。
- 全屏练习只改变布局，不改变键盘语义；练习中 `Esc` 先结束练习，再退出全屏。

### 8.5 窗口与全屏

- 主窗口为常规可缩放窗口；页面滚动区独立，播放条常驻。
- 练习全屏是窗口内全屏，不调用操作系统全屏 API，避免与 `Esc`、悬浮窗和全局热键冲突。
- 全屏时隐藏侧栏、顶栏和播放条，只保留练习舞台与全屏顶栏。
- 悬浮窗是独立透明窗口，不获取焦点、不进入任务栏，位置与透明度持久化。

## 9. 架构设计

### 9.1 进程边界

应用按 Electron 的渲染进程、预加载脚本、主进程三层组织：

- **渲染进程**：React 页面、试听、练习、悬浮窗 UI；通过 `@core` 调用纯 TypeScript 逻辑。
- **核心逻辑**：`src/core` 不依赖 Electron 与 DOM，包含模型、DSL、导入、音频分析、排键、练习判定和导出，可在 Node 中直接单测。
- **预加载脚本**：通过 `contextBridge` 暴露白名单 IPC API，渲染进程不直接访问 Node.js、文件系统或原生模块。
- **主进程**：窗口、托盘、存储、全局快捷键、悬浮窗、播放控制器、原生输入与窗口操作。

### 9.2 数据流

```
简谱文本 / MIDI / 音频
        │ 解析 / 导入 / 分析 / 量化
        ▼
      Score（绝对音高 + 绝对拍位）
        │ planPerformance()
        ▼
   PlaybackPlan（物理键位 + 毫秒事件）
        ├─→ Web Audio 试听（只出声，不注入）
        ├─→ PlaybackController → SendInput → 游戏
        └─→ 宏 / 键位表导出
```

同源性是架构的核心约束：任何输出路径都不能重新实现一套排键或时序逻辑。

### 9.3 主进程模块

- `PlaybackController`：绝对时间轴排程、sleep / 自旋混合等待、焦点与光标看门狗、停止与全量松键。
- `OverlayWindowManager`：悬浮窗创建、置顶、显隐、位置持久化与命令分发。
- `HotkeyManager`：全局快捷键注册、注销、冲突检测和录制期间暂停。
- `AppStorage`：设置与曲谱的原子读写、内置曲库播种、损坏容错。
- `AppTray`：托盘菜单与主窗口 / 悬浮窗显隐。
- 原生模块：通过 koffi 调用 `user32` / `winmm`，完成 `SendInput`、窗口枚举、进程名识别、前台切换、光标与窗口矩形校验、`timeBeginPeriod(1)`。

### 9.4 输入执行

- 键盘使用物理扫描码注入，规避键盘布局和输入法差异。
- 鼠标键作为八度 / 半音修饰，事件投递依赖光标位置。
- 演奏前尝试把目标窗口切到前台并确认光标在窗口内。
- 演奏中以固定间隔轮询焦点与光标；异常时立即停止并释放所有按键。
- 倒计时、开始、正常结束、停止、急停、失焦、光标离开和异常都走统一的清理路径。

### 9.5 打包与分发

- 使用 electron-builder 生成 Windows NSIS 安装包与便携版、macOS dmg / zip（x64 与 arm64）、Linux AppImage / deb。
- 原生模块与音频采样需要放在 asar 外，主进程按白名单读取。
- 可执行文件使用 ASCII 名称，规避中文文件名下的原生崩溃风险；窗口标题、快捷方式和安装界面仍使用中文产品名。
- 安装包以普通权限启动，注入前由应用内提权重启；不把管理员权限写死到安装清单。
- 不做代码签名与公证：macOS 仅做 ad-hoc 签名（Apple Silicon 必需），首次打开的放行方式随发布描述一并给出，细节见 [平台支持与发布](PLATFORM_SUPPORT.md)。

## 10. 算法设计

### 10.1 自动移调与排键

1. 合并连音、截断重叠，得到单声部音高序列。
2. 若移调为「自动」，枚举 -11…+11 半音，按「不可演奏数 × 10000 + 折返数 × 40 + 修饰键数 × 8 + |移调| × 0.5」计分，取最小。
3. 每个目标音高枚举可用物理组合；超音域时按八度折返，仍不可用则标记不可演奏。
4. 用动态规划选择全曲修饰键切换最少的组合：状态为上一层候选组合，转移代价为需要松开 / 按下的鼠标键数量。
5. 检查节奏可行性：相邻音过近（小于最小间距）时丢弃并警告；保持时长受时值、释放间隔和下一音起点约束。
6. 生成事件：修饰键按下 → 稳定 → 音符按下 → 保持 → 松开 → 反序释放修饰键；开头留白，结尾释放全部修饰键。
7. 校验：事件有序、无和弦、修饰键状态正确、结束无残留键。

### 10.2 时序参数

默认值是一组经过实机校准的工程折中：

| 参数 | 默认 | 作用 |
|---|---|---|
| 修饰键稳定时间 | 24ms | 先按住鼠标键，再按音符键 |
| 相邻音释放间隔 | 12ms | 避免两个音粘连 |
| 单音最短保持 | 40ms | 低于该值游戏可能不判定 |
| 修饰键切换间隔 | 6ms | 换音时调整鼠标键的间隔 |
| 开头留白 | 90ms | 保证第一个音的修饰键提前量 |

这些参数可在设置页调整；调整后计划实时重新生成。值越大越稳，但会拖慢快速乐句；产品不把某一组值描述为「绝对正确」。

### 10.3 MIDI 与音频

- MIDI：解析轨道 → 选轨 → 单音化 → 取首段 tempo → 量化 → 调性检测 → 生成 Score。
- 音频：起音与节拍用于切分和量化，YIN / 显著度用于音高，HPSS 用于抑制伴奏与打击，Viterbi 用于复音主旋律跟踪，后处理负责八度校正、碎音合并和最短音符过滤。
- 所有导入结果都带 `warnings` 与来源元数据；算法可以失败，但必须让用户知道失败在哪里。
- 转谱算法的升级应保持输入 / 输出契约不变，允许替换单声部、复音或未来可选的 ML 后端。

### 10.4 练习判定

- 以目标音的 MIDI 音高与拍点时间为准；同一音高的不同按法等价。
- 每次按键在判定窗口内匹配最近的未判定目标音；错音不消耗目标音，也不跳过当前目标。
- 超过窗口未按记为失误；命中后记录时间偏差，用于平均偏差与连击。
- 准确率分母包含已判定目标音与错音，避免「乱按」提高准确率。
- 练习会话与谱面渲染解耦：横向与下落式共享同一份步骤与时间轴。

### 10.5 宏生成

- 导出器是纯函数：输入 `PlaybackPlan` 与选项，输出文本与警告，不依赖 Electron 或文件系统。
- 每种格式只负责语法适配，不重新计算时间和按法。
- 中止机制必须简单可靠：AHK 使用 `playing` 标志与重新加载；Lua 再按触发键置标志，等待循环在毫秒级退出。
- 兼容性对照表作为单一数据源，同时供界面、导出文件和文档使用。

## 11. 安全与合规

### 11.1 风险模型

- 官方反作弊覆盖第三方模拟输入；本产品不提供任何规避能力。
- 注入需要管理员权限，UIPI 会静默丢弃低权限输入。
- 鼠标事件按光标位置投递，光标离开窗口可能导致修饰键失效或误点其他程序。
- 游戏版本更新可能改变键位、窗口标题或演奏界面状态。
- 宏导出把执行责任转移给宏软件，风险性质与软件内注入一致。

### 11.2 防护设计

- 首次启动强制风险确认，状态持久化。
- 管理员权限检测；未提权时阻止注入并给出提权入口。
- 目标窗口校验与可选自动切前台。
- 开始前把光标移入目标窗口；演奏中光标离开立即停手。
- 焦点看门狗轮询目标窗口，失焦立即停手。
- 任何停止路径都全量松键，包括正常结束、停止、急停、失焦、光标离开和异常。
- 会触发鼠标左 / 右键的曲谱需要额外安全确认。
- 输入通道自检让用户先验证链路，再进入游戏。

### 11.3 隐私

- 曲谱、设置、音频和试听均在本地处理，不上传服务器。
- 不收集遥测，不要求账号。
- 用户文件访问限于主动选择的路径；内部数据写入应用用户目录，采样读取使用白名单目录。
- 日志仅在显式开启调试时记录启动、窗口与输入诊断信息，不主动记录曲谱内容。

### 11.4 责任边界

- 软件不保证不被检测、不保证账号安全。
- 软件不判断用户所处场景是否允许自动演奏。
- 用户应在了解风险后自行决定是否使用，并承担相应后果。

## 12. 非功能需求

### 12.1 平台与运行

- 平台矩阵：Windows 10 / 11 x64（完整功能）；macOS 12+（Intel / Apple Silicon）与 Linux x64（编辑、导入、练习、试听、宏导出，不含游戏注入）。
- 游戏注入仅 Windows 提供；其他平台首次启动自动使用排练模式，并在设置页说明原因，不把不可用误报为故障。
- 桌面 Electron 应用；应用运行不需要网络，只有下载依赖或打开外部公告链接时会使用网络。
- 音频采样随安装包分发；应用启动后在后台解码，首次试听通常已经就绪。
- 数据保存在用户目录，升级不覆盖用户曲谱。

### 12.2 性能

- 编辑、切换页面和调整演奏参数应保持即时反馈；排键与计划生成在普通曲谱规模下不应造成可感知卡顿。
- 音频分析在普通 PC 上应在秒级完成，并在分析期间保持界面可响应。
- 演奏时序以毫秒为目标；UI 渲染不能影响主进程的输入排程。
- 长曲谱的谱面渲染与练习轨道需要避免每次时钟刷新都重绘整棵组件树。

### 12.3 可靠性

- 设置与曲谱原子写入，单文件损坏不影响其他曲谱和启动。
- 任何异常停止都先释放按键，再更新 UI 状态。
- 导入、导出和分析失败时保留用户已有内容，不产生半成品覆盖。
- 全局快捷键注册失败不影响其他功能，并明确显示状态。

### 12.4 可维护性

- 核心逻辑与 Electron / DOM 解耦，纯函数优先，便于单测。
- 输入、存储、热键、悬浮窗等平台能力封装在主进程，渲染层只通过 IPC 调用。
- 导出格式与兼容性数据集中管理，避免界面、文档和脚本各写一份。
- 设计令牌与组件契约集中管理，页面不写裸色值和一次性样式。

### 12.5 失败模式与恢复

| 现象 | 常见原因 | 恢复方向 |
|---|---|---|
| 游戏内完全无输入 | 未提权，UIPI 丢弃 | 以管理员重启并确认 UAC |
| 演奏刚开始就停止 | 游戏失焦或光标离开窗口 | 保持游戏前台，把光标放回游戏 |
| 高低音变成中音 | 修饰键未稳定或光标不在窗口 | 增大修饰键稳定时间，检查光标 |
| 快速音符漏音 / 粘连 | 保持时间或释放间隔不足 | 增大最短保持与释放间隔，或降速 |
| 逗号键无效 | 输入法拦截全角逗号 | 切换英文 / 半角输入法 |
| 悬浮窗不可见 | 游戏独占全屏 | 改为无边框窗口，或使用全局快捷键 |
| 全局快捷键无效 | 被系统 / 游戏占用 | 在设置页更换组合并查看注册状态 |
| 自检失败 | 安全软件拦截、远程桌面或焦点被抢 | 关闭抢焦点软件，提权后重试 |
| 音频转谱混乱 | 伴奏、混响或低音区旋律 | 改用 MIDI / 简谱，或调整模式与音域 |

## 13. 已知限制与取舍

### 13.1 游戏与输入

- 游戏绝对音高未公开，软件按相对音高建模；游戏实际发声以游戏为准。
- 键位表为固定预设，暂不支持逐键重映射；游戏改键时需要更新预设并校准。
- 悬浮窗在独占全屏下无法覆盖，这是系统限制，不是渲染问题。
- 悬浮窗不可聚焦，按钮点击手感依赖具体环境；全局快捷键是可靠兜底。
- 全局快捷键可能被占用；产品只能检测并提示，不能抢占。
- 高 BPM、密集音符、长时间连续演奏对时序最敏感，需要实机微调参数。

### 13.2 转谱

- 音频转谱基于传统 DSP，不是通用音频分离；强混响、掩蔽和低音区旋律仍可能出错。
- 复音模式只输出一条主旋律，不做真正的多声部分离。
- MIDI 多段变速只按第一段 tempo 处理；复杂和弦只保留单声部。
- 量化会移动音符，过于复杂的节奏可能被简化；产品应显示量化移动警告。
- 低音区口琴采样由 C4 降速生成，音色会比中高音更暗，这是采样音源的物理特性。

### 13.3 宏与导出

- 宏回放精度受宏软件 Sleep 分辨率限制，极快节奏可能有轻微抖动。
- 宏软件需要管理员权限；与软件内演奏同时启动会双触发。
- 其他品牌驱动不提供可导入脚本格式，只能录制到私有配置；统一推荐 AHK 或 CSV。
- AHK v1 与 v2 语法互不兼容，必须按本机安装版本选择。
- 导出文件不包含自动更新或版本检查，游戏改键后需要重新导出。

### 13.4 产品取舍

- **Electron 换 UI 质量与开发效率**：体积较大，但简谱排版、交互和样式实现成本低；音频 DSP 用纯 TypeScript 已能满足主旋律场景。
- **SendInput 而非驱动或硬件**：用户态、无内核组件、门槛低，但受 UIPI 与光标位置约束；硬件 HID 作为未来可选后端保留。
- **单声部而非多声部**：符合游戏口琴能力，也避免产生无法演奏的计划。
- **传统 DSP 而非重型 ML**：零依赖、离线、可测试；效果不足时可在同一契约下替换后端。
- **本地优先而非云曲库**：保护隐私、降低运维，但跨设备同步需要手动导入导出。
- **不提供反检测**：这是产品边界，也是风险声明的一部分。

## 14. 演进原则

- 新输入后端、转谱后端和导出格式都应复用既有 `Score` / `PlaybackPlan` 契约，不在 UI 层复制业务逻辑。
- 键位重映射应作为「预设 + 校准」能力加入，而不是散落在各页面的硬编码。
- 新增音频算法必须保留分析模式、置信度、警告与音域约束这些用户可见的边界。
- 新增宏格式必须接入兼容性数据源，并在导出文件中写明权限、触发与中止方式。
- 任何新功能都不能削弱风险确认、权限检查、焦点 / 光标保护和全量松键。
- 产品不引入账号体系、云端曲库、遥测或反检测能力。

## 15. 术语表

| 术语 | 含义 |
|---|---|
| 简谱 | 用 1–7、升降号、八度点和时值记号表示的音乐记法 |
| 音级 | 简谱中的 1–7，对应 do–si；0 表示休止 |
| 绝对拍位 | 以拍为单位的音符起始位置，四分音符为 1 拍 |
| 调号 / keyRoot | 简谱 `1` 对应的音高，0 = C … 11 = B |
| 基础八度 | `1` 所在的科学音高八度，4 表示 C4 = MIDI 60 |
| 物理组合 | 音键 + 八度偏移 + 半音偏移组成的实际按键方式 |
| 修饰键 | 鼠标左 / 右 / 中键，分别对应降八度 / 升八度 / 升半音 |
| 八度折返 | 超出音域时把音高上下移动一个或多个八度 |
| 移调 | 整首曲谱统一升降半音 |
| PlaybackPlan | 由 Score 生成的物理键位与毫秒输入事件计划 |
| 单音化 | 把复音素材整理成单声部旋律 |
| HPSS | 谐波 / 打击分离，用于抑制伴奏和鼓点 |
| Viterbi | 在候选音高序列上求最优路径的动态规划方法 |
| 判定窗口 | 允许按键与目标拍点相差的时间范围 |
| 排练模式 | 只走时间轴、不发送按键的演奏模式 |
