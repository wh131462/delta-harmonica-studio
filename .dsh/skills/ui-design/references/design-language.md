# 设计语言与理由

## 目标场景

用户在游戏窗口旁操作这个工作台：选曲 → 确认输入 → F9 开始 → 回游戏。窗口经常被切走、被遮挡，用的时间多是晚上。因此界面必须：

1. **暗、低刺激**：大面积深色，减少白色纸面与高饱和色块，长时间看不刺眼。
2. **一眼可读的层级**：当前曲谱、当前页面、下一步操作，三者位置固定，用字号和留白区分，而不是靠彩色边框。
3. **动作收敛**：真正会改变状态的操作少而显眼；其余操作降权到工具区，避免误触。

## 视觉隐喻

「夜里的琴房」：石墨色的墙、一盏黄铜色的聚光灯、谱纸是暖色的。因此：

- **琥珀（黄铜）只做聚光灯**：主操作、选中、正在演奏。它出现在哪里，用户的目光就该去哪里。
- **青蓝是信号灯**：只表示系统层面的信息（输入通道就绪、焦点、链接）。它不参与品牌表达。
- **纸面是唯一的暖色区域**：谱面用暖黑底 + 米色墨，形成"灯下谱纸"的对比；如果页面别处也出现米色，这个隐喻就失效了。
- **不用渐变做装饰**：主按钮、卡片、页面背景全部是纯色；不使用光晕、内高光、装饰性投影。
- **不做卡片描边**：`.card` 只有底色和圆角，靠 `--surface-2` 与页面底色（`--canvas-elev`）的明度差分层；描边只留给可交互控件。

## 分层手段（优先级从高到低）

1. **字号与字重**：26 → 17 → 14 → 13 → 12 → 11。
2. **留白**：区块间 20–24，组内 8–12。
3. **表面明度**：canvas → surface-1 → surface-2 → surface-3。
4. **1px 描边**：只在需要"可点击边界"时出现（输入框、次级按钮），不做装饰性描边。
5. **强调色**：最后手段，且面积受控。

反例（旧界面的问题，禁止回归）：

- 每个区块都是同一种带边框的深色卡片，于是"卡片"不再表示分组，只剩装饰。
- 琥珀色同时用于导航高亮、主按钮、开关、滑杆、快捷键标签、图标，导致没有任何一处是真正的焦点。
- 同一条"已以管理员权限运行"在顶栏、侧栏、设置页横幅、自检结果里各出现一次。
- 米色谱面嵌在深色界面中，边界生硬，像贴图而不是界面的一部分。

## 减法原则

「简约」不等于留白变多，而是**去掉一切不承担决策的信息**：

- 页面头不加眉标（`eyebrow`）、不写能力清单；标题 + 一句操作说明即可。
- 卡片标题不加图标；图标只出现在动作按钮和导航上。
- 不做统计条/指标卡，除非数字会改变用户下一步动作（方案库的总数、收藏数不改变任何操作，删掉）。
- 常驻区域只保留全局上下文：顶栏 = 当前曲谱名 + 状态；侧栏 = 品牌 + 导航 + 权限；播放条 = 曲名 + 试听 + 演奏。
- 同一数据不在两处出现：音符数/时长一旦在播放条常驻，编辑器与页头就不再重复。
- 品牌 slogan、版本号、"仅供娱乐" 之类信息移到设置页；侧栏底部只留可点的权限状态。
- 设置卡片不写卡片副标题，解释放进具体设置行的说明里。
- 能靠 `title`/tooltip 承载的细节，不要占用常驻版面。

## 图标

- 统一 `components/Icon.tsx`：24 视框、1.7 描边、圆头圆角连接、`currentColor`。
- 尺寸：导航 16、按钮内 13–15、空态 20。
- 图标永远搭配文字或 `aria-label`，不单独承载语义；**卡片标题、页面头不放装饰图标**，按钮图标只用于动作识别（保存/导入/播放/停止）。
- 不引入第三方图标库；缺图标先补 `Icon.tsx` 的同风格路径。

## 动效

- 克制：页面进入 240ms 位移 5px；悬停只有颜色与背景变化；开关 180ms 滑轨。
- 演奏态的呼吸动画只改透明度，且 `prefers-reduced-motion` 下静止。
- 不做弹跳、不做缩放进入、不给普通卡片加悬浮位移。

## 排版细节

- 中文标题字距 +0.01em 以内，微型英文标签 +0.14em 并大写。
- 数字（BPM、时长、音符数）统一 `.num`，等宽对齐；时间码用 `--font-mono`。
- 说明文字最多 2 行，超过就换一种表达或折叠进 `details`。
- 长列表/长文本必须自带滚动容器，不撑破页面高度。

## 声音与反馈

这个产品本身和声音强相关，但界面里不要用声音做反馈；用一次 Toast、一个状态徽标、一次按钮进行时即可。演奏中的视觉反馈集中在：播放条进度线、谱面当前音符高亮、侧栏 `LIVE` 标签——三处且同步。
